# Spec scenario-to-task map — 001-survey-management

Regenerated by the `/speckit-analyze` gate from the `US<n> scenario <m>` and `SC-0nn` annotations
carried inside `tasks.md`, so this file cannot drift from the task list by hand. Regenerate it with
the script in `analysis.md` whenever `tasks.md` changes.

## What this file is, and is not

- It **is** the scenario → _task_ map: which task in `tasks.md` is responsible for asserting each
  acceptance scenario. Every id below exists in `tasks.md` (`T001`–`T148`).
- It is **not** the scenario → _test name_ map. That one can only be written after the tests exist,
  and `T148` owns it: "Map every spec acceptance scenario to the named test that covers it, in a
  table in the implement task's comment." The S9 Verify gate reads `T148`'s output, using this file
  to check nothing was dropped.
