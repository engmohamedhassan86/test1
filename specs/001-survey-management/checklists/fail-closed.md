# Fail-Closed Configuration Checklist (Principle I): Dynamic Survey Viewer

**Purpose**: Validate that the requirements make the viewer fail closed on every path by which a bad or
absent configuration can reach it. Principle I is non-negotiable: when in doubt the viewer renders an
error, never a guess and never a partial survey. This checklist tests whether the requirements say that
for every doubt the system can actually be in — not only for a config that parses and fails a rule.

## Distinguishing the three negative outcomes

- [ ] CHK012 Are "unknown key", "broken config" and "catalog unavailable" specified as three distinct screens, each with its own trigger? [Clarity, Spec §FR-050, §FR-066]
- [ ] CHK013 Is the precedence decided when a key cannot be resolved because the manifest itself is unavailable, so the viewer never reports an unknown key it could not have known? [Edge Case, Spec §FR-066]
- [ ] CHK014 Is a manifest entry resolving to a missing or invalid config required to leave the rest of the catalog working? [Coverage, Spec §Edge Cases]
- [ ] CHK015 Is an empty manifest specified as a normal outcome rather than an error? [Clarity, Spec §FR-048]
